Thin Clients /

Settings

What every thin client's stream uses, as spectre-qt's Settings dialog sets it on a desktop, and the clients' own settings. A change reaches each client at once. Stream settings apply from its next sign-in, and running sessions keep what they started with; Power applies at once. Thin clients are always fullscreen kiosks, so spectre-qt's fullscreen and window-following options don't apply.

Display

Decoding

Codec

Once a region of the screen stops changing, the host re-sends it losslessly so text and UI become pixel-exact. Costs the host a frame readback per frame. Unticked, every session starts with it off; either way the session menu's Lossless Refinement row switches it. The lowest latency there is, at several hundred Mbit/s: offered first only when the host is directly reachable over a wired link of 1 Gbit/s or more, and used only if the host has turned it on.

Network

Input

Mirror controllers plugged into a client onto the host as virtual gamepads (up to four), if the host supports it. Send a client's microphone to the host, where applications see it as a microphone, if the host supports it. Off by default.

Diagnostics

Run spectre with its debug log on: more detail in the client's journal, and in the client's half of a support report (wraith --report on the host). For chasing a problem; off by default.
