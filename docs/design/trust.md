# Identity and trust

Who trusts which certificate, and how a session token proves a login.
The normative rules are gdp-spec.md §2.3 (certificates) and §4.8 (the
token). Code: the `gdpnet` crate, `host/authticket` (tickets and tokens),
wraith's `session/session_cert.*` and `session/token.cpp`, and
libgdp's TLS verification on the client side.

## Certificates

| Certificate | Held by | Trusted by |
|---|---|---|
| Host certificate (`/etc/ghost/host-{cert,key}.pem`, key readable by the `ghost` group) | ghostd | spectre-qt, trust on first use, in `~/.config/spectre/known_hosts`; Veil, pinned at join |
| Session certificate (throwaway, per session) | wraith | spectre, through `Redirect.cert_sha256`; Veil's gateway, the same way |
| Veil lobby certificate (`/etc/ghost/veil-{cert,key}.pem`) | veild | spectre-qt (first use), joined hosts and Wisp clients (configured fingerprint) |
| Veil web certificate (`/etc/ghost/veil-web-{cert,key}.pem`) | veild | browsers, by CA or by exception |

A pin is the SHA-256 of the certificate's DER as 64 lowercase hex
digits (`gdpnet::sha256_hex`). Every certificate ghost generates is
self-signed. A TLS handshake never fails on validation; the peer decides
whether to trust the certificate once the handshake is done and before
it sends anything. The handshake still verifies the signature, so the
peer must hold the key for the certificate it presents.

- **The host key stays with ghostd.** wraith runs as the session's user,
  and anything it can read, the user can read. Sharing the host key with
  wraith would let any user impersonate the host to other users. So each
  wraith generates an ECDSA P-256 certificate at startup, held in memfds
  and never written to disk, and reports its fingerprint in
  `SessionReady`. ghostseat reports it in `STATUS`, so a reattach can
  vouch for it too, and sends it in `Redirect.cert_sha256` over the
  lobby connection spectre already trusts. spectre requires the session
  connection to present exactly that certificate. The most a user can do
  with their own session's key is impersonate their own session.
- **CA-issued lobby certificates.** A lobby certificate that chains to a
  CA the client trusts, and is valid for the name dialed, is accepted
  without a pin or a prompt (gdp-spec.md §2.3). veild can present its web
  certificate on `gdp/1` for that (`[lobby] clients_use_web_cert`, off by
  default). A host joined to Veil keeps a stable self-signed certificate,
  because Veil pins it.
- **Host and Veil pin each other.** On the host channel ghostd presents
  its host certificate and pins Veil's (`gdpnet::PinnedServer`); veild
  accepts any client certificate during the handshake
  (`gdpnet::AnyClientCert`) and checks it against the device's stored
  pin once it knows which device is connecting.

## Session tokens

ghostseat and wraith share a 32-byte session secret, generated by
ghostseat when it opens the session and sent to wraith in
`SessionInit`; ghostd, which only carries the tokens, never holds it. A token is
`base64url(nonce ‖ expiry ‖ HMAC-SHA256(secret, uid ‖ nonce ‖ expiry))`
with a 16-byte random nonce and a little-endian expiry (gdp-spec.md §4.8
has the layout and a test vector, which both `authticket`'s test and
wraith's `token_test.cpp` check). ghostseat mints tokens valid for 30 s,
one per spent authentication ticket: with the `Opened` reply, or for a
reattaching login on a `MintTokenRequest` carrying that login's ticket
([login and sessions](login-and-sessions.md#the-login-path)). So ghostd,
which carries tokens but holds no secret, can't attach a viewer to a
session nobody just logged in to. wraith checks the MAC and the expiry
against its own clock.

A token is single-use: wraith's `RedirectTokenGate` remembers the nonce
of each token it accepts until that token expires, and refuses it after
that. The nonce is the key, not the string, since the last base64url
character carries two bits the decoder ignores. spectre-qt and Wisp's
greeter hand the token to spectre in `SPECTRE_TOKEN`, not on the command
line, which other local users can read; spectre unsets it once read.
Through Veil's gateway, veild swaps a token of its own for the host's
(see [Veil](veil.md#the-gateway)).

## QUIC sockets

ghostd and veild bind UDP sockets on `[::]` with `IPV6_V6ONLY` cleared,
so one socket serves both families whatever `net.ipv6.bindv6only` says,
as wraith's libgdp sockets do (`gdpnet::bind_dual_stack`). Peer
addresses are unwrapped from their IPv4-mapped form
(`gdpnet::canonical`) before they reach logs, penalties or `PAM_RHOST`.
Each socket asks for 8 MiB of kernel buffer in each direction (falling
back to 2 MiB), since the default ~208 KiB overflows within milliseconds
of a video burst; Linux caps the request at `net.core.rmem_max` /
`wmem_max`.
