# Wisp thin clients

Wisp is a network-booted thin-client image whose greeter signs users in
to Veil and runs spectre in kiosk mode (`client/wisp/`). Each client also
runs `wisp-agent`, which keeps it known to Veil so administrators can see
and manage it. Code: `client/wisp/agent/`,
`host/veil/src/thin_clients.rs`, `host/veil/src/web/thin_clients.rs`.
Wire format: gdp-spec.md §14 (`libgdp/proto/wisp.proto`).

## The agent's connection

`wisp-agent` is a root service holding one QUIC connection to Veil's
lobby port with ALPN `wisp/1` for as long as the client is up. It uses
libgdp's `ClientConnection`, pinned to the `veil_cert=` boot argument as
the greeter is, with a 10 s keepalive inside both sides' 30 s idle
timeout. One bidi stream carries `WispEnvelope` frames:

- **`WispHello`**, first: `wisp_key=` from the kernel command line, the
  MAC of the default route's interface (the client's identity),
  hostname, addresses, architecture, `/etc/wisp-release`, boot time, and
  `SystemInfo` (CPU, memory, GPUs, displays with their refresh rate from
  the EDID, link speed, and the decoders `spectre --probe-decoders`
  reports), plus the running session if any.
- **`WispWelcome`** back, with the `ClientProfile`; then **`WispProfile`**
  whenever an administrator saves a new one.
- **`WispSession`** from the client when a session starts or ends.
- **`WispCommand`** from Veil when an administrator presses End Session,
  Restart or Shut down on the client's page (offered only while it is
  online, and audited). The agent runs `systemctl --no-block reboot` or
  `poweroff`, or for a log out sends `SIGUSR1` to the spectre whose pid
  the greeter wrote to `session.json`. spectre takes `SIGUSR1` as its
  menu's End Session (a `LogoutRequest`, so the desktop on the host ends)
  and exits when the host has ended it. If it hasn't within 30 s, the
  agent sends `SIGTERM` (a plain disconnect).

## The key

One 32-byte hex secret for every client, generated by
`make install-veil` into `/etc/ghost/veil-wisp.key` (`root:veil 0640`)
and named by `[thin_clients] key`. `veild wisp-env` prints the boot
server's `.env` lines (`VEIL_CERT_SHA256`, `WISP_KEY`); the boot server
passes the key as `wisp_key=`. It keeps out only machines that can't
reach the boot network: anyone who can boot the image can read it.

- veild compares it in constant time. A wrong key (or no key file, which
  veild warns about at start) closes with `AUTH_FAILED` without
  penalising the address, so clients still on an old key after a
  rotation don't lock their own greeter's sign-ins out.
- The MaxStartups slot is released as soon as the key checks out, so
  long-lived agents never hold unauthenticated slots. A missing or
  malformed hello is penalised like a lobby's.
- The agent backs off from 1 s, doubling to 60 s with ±25% jitter (5 min
  after `AUTH_FAILED`), so a fleet doesn't reconnect in lockstep after a
  veild restart.

## Veil's side

veild keeps live connections by MAC (a newer one replaces an older one)
with their sessions in memory, and `thin_clients (mac, name, first_seen,
last_seen, last_report)` in the database, so offline clients stay listed
under their admin-given names. The profile is one JSON row in `settings`
(`thin_client_profile`), defaulting to SpectreSettings' defaults, held in
a `watch` channel every connection's push task follows.

Admin UI: Thin Clients lists every client (name or hostname, status,
address, MAC, current user and host, uptime, last seen; refreshed live);
a client's page shows its report and session, edits its name, and
removes it while offline; Settings edits the profile, laid out like
spectre-qt's dialog minus what a kiosk makes moot. Renames, removals and
profile changes write `audit` rows, the last naming each field changed.

## On the client

`/run/wisp` (`root:wisp 0775`) is the only link between agent and
greeter. The agent replaces `profile.json` atomically with every field
written; the greeter writes `session.json` when spectre starts and
removes it when spectre exits, and the agent watches the directory with
inotify.

The greeter reads the profile at every spectre launch into
`SpectreSettings` (`client/spectre-settings/`, shared with spectre-qt)
and adds `-K` (kiosk). The session token goes in spectre's environment
as `SPECTRE_TOKEN`, and so does `SPECTRE_LOG=debug`
when the profile's `debug_logging` is set (the Client Settings page's
"Enable Spectre debug logging"). A profile change therefore applies from
the next sign-in, never to a running session. The one setting of the client's
own, `display_sleep_minutes` (default 20, 0 never), applies at once: the
greeter runs `swayidle` with `wlopm --off`/`--on` under labwc. spectre
lets the screen sleep during a session, except for a minute after
gamepad input, which the compositor never sees.

## Limitations

- The shared key is readable by anyone who can boot the image.
